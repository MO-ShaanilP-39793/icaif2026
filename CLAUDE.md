# icaif2026

Our entry in the ACM ICAIF 2026 Trading Agent Competition (Codabench 99): hourly
long-only weights for 30 US large caps, 7 rounds a day, 0.1% fee, ranked on return,
Sharpe, max drawdown and turnover. This is its own repo (GitHub,
MO-ShaanilP-39793/icaif2026), cloned inside an alphaBT checkout for context. It imports
nothing from alphaBT, and alphaBT never tracks it (`icaif2026/` is in alphaBT's
`.git/info/exclude`).

## Read first

- `README.md`: every data source, trap, cross-check and result so far.
- The design doc, [ICAIF 2026 — System Overview](https://claude.ai/code/artifact/fc65ac28-7695-4dce-845e-c35040bae282).
  Its tabs are Overview, Ensemble models, Daily model, Data pipeline, Deployment,
  Results and Roadmap. The Data pipeline tab lists the design choices, with a column for
  the owner's take. **The Roadmap tab is the plan:** six steps toward an LLM desk that
  uses the HAR vol forecast, the daily ensemble, news and a portfolio journal to decide
  rebalancing and profit booking. The owner set all six as the minimum. Tick its tasks
  and update its Status column as work lands. The older "ICAIF 2026 Trading Agent —
  Design" doc is superseded; read it only for the original reasoning.
- `git log`: commit messages say why each change was made and what was left out.

## Environment

```bash
.venv/bin/python -m pytest -q          # whole suite, ~85 s
.venv/bin/python tools/<name>.py       # every experiment is a tool script
```

Python 3.13, pandas 2.3.3, numpy 2.3.5 and AutoGluon 1.5 (which pins both). Install
with `.venv/bin/pip install -r requirements.txt`.

## Data, and where it lives

Nothing under `data/` or `output/` is in git. The organizer panel is licensed to
participants, and the rest is large.

| Path | What | Made by |
| --- | --- | --- |
| `data/hourly_market_data_2021_2026.parquet` | Organizer panel (:00 grid) | Codabench Files tab |
| `data/public/yahoo_{60m,30m}_<date>.parquet` | Yahoo intraday, dated snapshots | `tools/data_report.py` |
| `data/public/alpaca_30m_<date>.parquet` | Alpaca 30m bars, 2016 on | `tools/alpaca_report.py` |
| `data/external/*_<date>.*` | Daily universe, context, S&P membership, earnings | `tools/enrich_data.py` |
| `output/ag/`, `output/preds/`, `output/live/` | Trained models, out-of-sample predictions, live rounds and rehearsals | `tools/train_walkforward.py`, `tools/live_runner.py` |

Loaders read the latest dated snapshot. Yahoo's old intraday windows can't be
refetched, so copy `data/public/` from a teammate rather than regenerating it.
`reports/*.json` is tracked; `reports/*.csv` is regenerated by the tools.

**The copy of record is `s3://shaanil/icaif2026/`** (`data/`, `output/`,
`reports/*.csv`), mirroring the repo's paths. It holds what can't be rebuilt: the old
Yahoo windows and the news archive (`data/external/news/`, the only copy). Pull with
`aws s3 sync s3://shaanil/icaif2026/data data` (and `output`, `reports`); push after
new data or a retrain with the same command reversed. Never sync `.env`, `.icaif/` or
`.venv`. The bucket also holds alphaBT production prefixes (`dashboards/`,
`live_books/`, `alpha_strategies/`), so write only under `icaif2026/` and never sync
with `--delete` from the bucket root.

## Invariants that fail silently when broken

- **Alpaca is the organizer's vendor** (0 bps against the panel). Labels, intraday
  information bars and simulator fills use Alpaca's :30 opens from 2016.
- **No look-ahead.** A decision sees only bars ended by its deadline. Daily features
  are as of the prior close (shifted one session). Labels and folds are purged on
  each label's end. Each of these has a test that rewrites the future and requires
  the past to be unchanged; keep those tests passing, and add one for any new feature.
- **Never forward-fill a price.** A stand-in is a zero return that never happened;
  record the hole instead.
- **Half-days** live in `calendar.EARLY_CLOSES`, and a test checks them against the
  Alpaca data both ways.
- **Weights go through `weights.safe`** (the 1e-6 grid): the organizer's Decimal check
  rejects 0.1 + 0.2.

## Credentials and network

- `.env` holds the Codabench token and Alpaca keys; `.icaif/` holds the one-time team
  token, which is never reset. Never commit, print or log them. EDGAR needs
  `SEC_USER_AGENT="<name> <email>"` in the environment.
- The corporate Netskope proxy re-signs some hosts. Python HTTPS goes through
  `icaif.net.ssl_context()` (truststore, i.e. macOS verifies). Never turn
  verification off.
- Nothing uploads to Codabench or registers except a deliberate, human-approved
  action. `tools/live_runner.py` uploads only with `--live` and an arm file that the
  owner writes with `arm` at a terminal; never run `arm` for them.
  `tools/live_dry_run.py` writes a decision to disk and stops.

## Working here

- Ask before any run measured in minutes (training, sweeps, long fetches).
- "Push" means `git push origin main` (GitHub). This repo has no other remote.
- House style, as in alphaBT: comments and docstrings explain the silent failure a
  line prevents, not the mechanics. Test names are sentences describing that failure.
  Commit messages give an imperative subject, then why: what was wrong, what it would
  have looked like, and what was left out.
- Don't edit `starter-kit/`: it's the organizers' kit, vendored verbatim.
