# Journal, 2026-10-16: the VM wakes each weekday to report Official's metrics

Written by the personal-laptop session for the office-laptop session. Read
`JOURNAL_2026-10-12.md` first. It holds no secret.

## The short version

- Official is holding the 13-name entry (submission 1583). Nothing is armed or running.
- **The VM is no longer simply off.** A GCP instance schedule starts it at **21:30 ET every
  weekday until Oct 31**. A boot hook pushes the day's metrics to the owner's phone
  (07:00 IST) and powers the VM off again, about 3 minutes later.
- Code: `tools/daily_report.py` (`b79f240`, `8c09ca5`).

## Why

The server hides Official's metrics (`/api/v1/me/metrics` returns HTTP 409), and its NAV
lags the rounds by hours. The owner wanted the four metrics every day.

## How it works

- **The estimate.** `tools/daily_report.py` marks the held book to market on Alpaca's 30m
  opens at each round's execution time, and applies `starter-kit/docs/evaluation.md`:
  - period returns from B_1 = $1M, so the fee is in period 1;
  - Sharpe = 42 x mean / sample sd;
  - drawdown over the endpoints and the 16:00 closes;
  - turnover as the mean of round notionals.

  Shares are read from the server's book each time. That is exact only while the round-1
  book is held. The server's NAV is printed beside the estimate, and on Oct 16 they matched
  to the cent.
- **GCP.** Resource policy `icaif-daily-report` (us-east4): start at `30 21 * * 1-5`,
  America/New_York, expiring 2026-10-31. It is attached to `icaif-live`. The Compute
  Engine service agent was granted `roles/compute.instanceAdmin.v1` (the owner ran it);
  without that role a scheduled start fails silently.
- **On the VM.**
  - The crontab line `@reboot ~/icaif_boot.sh` waits 60 s, runs
    `daily_report.py --boot` (log: `output/live/alerts/daily.log`), and powers off on any
    exit code except 3.
  - `--boot` reports only on weekdays between 21:15 and 22:30 ET, and exits 3 otherwise.
    So **a VM started by hand stays up**; this was checked on Oct 16.
  - A failed report pushes "Official daily report failed" and still powers off.
- **Push only.** ntfy.sh refuses anonymous email (HTTP 400), so the owner chose push only
  and `NTFY_EMAIL` was removed from the VM's `.env`. The code sends the push first and
  tries any email separately, so a refused email can't lose the push.

## Traps

- **Don't detach the schedule or remove the boot hook** before Oct 31 unless the owner
  says so. Remove both after the phase:
  `gcloud compute instances remove-resource-policies icaif-live --zone us-east4-a --resource-policies icaif-daily-report`,
  then delete the `@reboot` crontab line.
- **Working on the VM between 21:15 and 22:30 ET on a weekday?** Any reboot in that window
  reports and powers off.
- **A trade after round 1 invalidates the estimate.** The shares would no longer be those
  of the whole phase. Nothing is planned to trade.
